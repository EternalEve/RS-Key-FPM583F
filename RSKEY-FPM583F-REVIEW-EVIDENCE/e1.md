## 调查边界

原复跑包装命令没有显式超时器，TERM trap 只记录信号后退出 143。标准客户端夹具的 `terminate()` 只针对其拥有的模拟器；本轮未发现项目代码向外层或进程组发送 TERM 的路径。

已只读核对与原会话编号对应的本地启动命令及相关执行日志。现存底层日志不覆盖原异常时段，无法恢复历史信号发送方；未把日志缺失或本轮未复现当作项目、Nix 或 Codex 的归因证据。

默认沙箱不允许 ptrace，也不能写 Nix 缓存锁；启动跟踪和固定 Nix 环境使用了执行权限。进一步附加到已运行的最外层 shell 仍被内核 ptrace 策略拒绝，故第二轮改为从启动时跟踪该 shell，没有调整系统策略。首轮跟踪器作为父进程；第二轮将跟踪器放入独立会话，核对最外层 Bash 的直接父进程为 Codex，原进程组不变。

## 再次采集

以下内容作为一次性 shell 脚本，从仓库根目录执行。每次新建证据目录，保留历史日志。需要 Linux 和本机 `strace`；本轮使用 6.19，仅用于主机诊断，没有新增固件或 Nix 依赖。末尾 `exec` 替换该一次性脚本的 shell，使最外层也在跟踪范围内。

```bash
#!/usr/bin/env bash
# SPDX-License-Identifier: AGPL-3.0-only
# Copyright (C) 2026 RS-Key contributors

set -eu
mkdir -p target/fpm-review-evidence
e1_dir=$(mktemp -d "$PWD/target/fpm-review-evidence/e1.XXXXXX")
printf 'E1 evidence: %s\n' "$e1_dir"
cat > "$e1_dir/run.sh" <<'SH'
#!/usr/bin/env bash
# SPDX-License-Identifier: AGPL-3.0-only
# Copyright (C) 2026 RS-Key contributors

set +e
e1_dir=$1
shift
status_file=$e1_dir/status.txt
printf 'SPDX-License-Identifier: AGPL-3.0-only\nCopyright (C) 2026 RS-Key contributors\n' > "$status_file"
trap 'printf "outer_signal=TERM\n" >> "$status_file"; exit 143' TERM
date -u '+started=%FT%TZ' >> "$status_file"
ps -o pid,ppid,pgid,sid,comm -p "$$,$PPID"
NIX_CONFIG='experimental-features = nix-command flakes' nix develop --offline --no-update-lock-file \
  -c env CARGO_NET_OFFLINE=true CARGO_BUILD_JOBS=2 bash -x scripts/bio-client.sh "$@"
runner_status=$?
printf 'outer_status=%s\n' "$runner_status" >> "$status_file"
date -u '+finished=%FT%TZ' >> "$status_file"
exit "$runner_status"
SH
exec strace -DDD -f -ttt -s 160 \
  -e trace=kill,tgkill,tkill,wait4,waitid,exit_group,execve \
  -e signal=SIGTERM,SIGCHLD -o "$e1_dir/processes.strace" \
  bash "$e1_dir/run.sh" "$e1_dir" "$@" > "$e1_dir/runner.log" 2>&1
```

若再次出现 143，先看最外层 PID 的 `SIGTERM` 行及 `si_pid`，再核对该 PID 的身份、pytest 的 `wait4` 结果、清理进程和脚本的退出顺序。仅有 pytest 汇总、最后一行 `rm` 或数值 143 都不足以确定发送方。若发送进程未被本次跟踪覆盖且已退出，其身份仍可能需要当时的执行器日志，不能从 PID 数值猜测。

上述脚本保存为 `e1-run.sh` 后，可用以下两个短控制核对采集方式。它们分别预期退出 **1** 和 **143**；两条命令各自运行，保留工具的实际退出结果，不应作为普通通过用例收集。第二条把目标设为该一次性 shell 自身，再通过 `exec` 保持 PID；不要把环境变量设为其他进程。
